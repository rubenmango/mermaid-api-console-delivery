04

Product rules

How the console behaves. Strings are literal; copy deck lives in the handoff.

Keys

  • Full key once, right after creation; then masked mmd_0889••••••b574.
  • Key emails never include the secret.
  • Row menu: Rename, Copy key ID, Revoke key. Revoked keys show Restore.
  • Revoked: calls are refused and cost 0 credits.

Greeting

  • Get started heading uses the signed-in user’s first name: “{first name}, let’s get started” (e.g. “Ruben, let’s get started”).
  • Same name source as the account menu; never a hardcoded name.

Agent prompt

  • Card: “Set up with your coding agent” · “Reads your key from MERMAID_API_KEY.”
  • Button Copy prompt → Copied.
  • Manual setup: export the key, then one curl to /v1/render.

Credits

  • Every plan has a monthly allowance; resets the 1st, 00:00 UTC; no rollover.
  • Allowance first, then purchased credits.
  • Allowances shown: Free 25 · Basic 250 · Plus 1,000 · Premium 5,000 · Enterprise custom (to confirm).

Packs

  • 5,000 / $5 · 10,000 / $10 · 15,000 / $15 · custom in multiples of 1,000.
  • CTA follows the pack: “Buy 5,000 credits for $5.00”.
  • Stripe Checkout: confirm → Stripe → back to Billing → Payment complete alert.

Auto top-up

  • Off by default. On: buy when the balance falls under 500.
  • Active: summary line + Edit.
  • No saved card: Stripe saves one first.

Limits

  • Spend limit caps purchased credits per month.
  • Low-balance email default 25 credits (a tenth of the allowance).
  • Off collapses the card to its header.

Members vs admins

  • Members: own keys, their share, org usage; no admin actions.
  • Admins: all keys, overrides, revoke, consumption, pool split, burst.
  • Admins see names and last 4 characters, never the secret.

Recent calls

  • Filters: Status, Endpoint, Key (dashboard only).
  • Empty filter: “No refused calls in the last 30 days.”
  • Refused or failed calls cost 0 credits.

Purchases

  • Only API credit purchases. Columns: Date, Credits, Amount, Taken back, Buyer, Invoice.
  • Empty: “No API credit purchases yet.”
05

Design rules

How the screens are built. Values on the Styles page.

Foundation

  • Coral Foundations + Iconography; tokens over raw values.
  • Dark mode only.
  • One pink primary per screen; everything else Secondary, Ghost or Link.
  • No explanatory notes inside screens. Short copy, one-line subtitles.

Surfaces

  • App, sidebar, top bar storm-975. Cards storm-950 + 1px storm-800, radius 8.
  • Hover storm-800 · selected pill storm-700.

Card header

  • Inline by default, ~48 tall. With actions: subtitle 16 px after the title.
  • Alone: subtitle pinned right.
  • Stacked only when the subtitle can't fit at 1024 wide.
  • Bottom divider only when the card has a body.

Shell

  • Sidebar 240: Dashboard · Access · Spend · Resources.
  • Top bar 60: breadcrumb · search 360 × 32 · mode toggle · credits · Documentation.
  • No avatar in the top bar; account row lives in the sidebar.

Tables

  • Fixed column widths that match headers; numbers right-aligned.
  • Equal row heights, 1px dividers.
  • Actions and badges in fixed right columns.

Controls

  • Buttons 36 and 32. Labels short; the main CTA keeps its amount.
  • Billing tabs: outlined segmented pill, not underline.
  • Switch centred on the header row, 16 px from the right edge.

Motion

  • Only for a user action or a page change. Nothing loops except the sign-in jellyfish (ambient, slow, always rising; still under reduced motion).
  • Log in → Signing in is one scene: the copy softens away, the screen dims, the card morphs, then the reef brightens back (about 0.9s + 0.7s).
  • 120 / 200 / 320 ms; ease-out to settle, spring for menus.
  • Respect prefers-reduced-motion everywhere.

Feedback

  • Every action answers within 520 ms: spinner, then result.
  • Destructive actions confirm in a dialog; the row then changes state and flashes.
  • Disabled buttons say why (“Choose a multiple of 1,000 credits”).
